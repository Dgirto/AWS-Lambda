¿Qué es y para qué sirve?

El conector AWS Lambda permite que el agente de Ruvic invoque tus funciones serverless. Una vez configurado, puedes pedirle al agente cosas como:

  • “Ejecuta la función procesar-pedido con el id 4521 y dime qué respondió.”
  • “¿Qué funciones Lambda tenemos desplegadas?”
  • “Revisa los logs recientes de la función enviar-reporte para ver si falló.”

Operaciones soportadas:

Operación Qué hace
lambda.list_functions Lista las funciones Lambda de la región configurada
lambda.invoke Invoca una función con un payload JSON, de forma síncrona o asíncrona
lambda.get_logs Consulta los logs recientes de una función en CloudWatch, para revisar el resultado de invocaciones pasadas
Este conector ejecuta código lambda.invoke dispara la ejecución real de la función, con todos sus efectos secundarios (lo que sea que la función haga). Se recomienda restringir el acceso IAM a un prefijo de nombres de función dedicado a Ruvic.

Prerrequisitos

  • Una cuenta de AWS con al menos una función Lambda ya desplegada.
  • Acceso a la consola de IAM para crear un usuario y su policy, solo durante la configuración inicial.
  • La región de AWS donde están desplegadas las funciones (ej. us-east-1).

Configuración en el fabricante

Vas a crear un usuario IAM dedicado para Ruvic, con permiso de invocación restringido a las funciones que le corresponden. No reutilices credenciales root ni las de otra aplicación.

  1. Define un prefijo de nombres para las funciones que expondrás a Ruvic.

    Por convención, usa un prefijo dedicado (ej. ruvic-*) al nombrar las funciones que quieres que el agente pueda invocar. Esto permite escribir una policy IAM precisa en el siguiente paso.

  2. Crea la policy IAM.

    En IAM → Policies → Create policy → pestaña JSON:

    {
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["lambda:ListFunctions"],
      "Resource": "*"
    },
    {
      "Effect": "Allow",
      "Action": ["lambda:InvokeFunction"],
      "Resource": "arn:aws:lambda:*:*:function:ruvic-*"
    },
    {
      "Effect": "Allow",
      "Action": ["logs:DescribeLogStreams", "logs:GetLogEvents"],
      "Resource": "arn:aws:logs:*:*:log-group:/aws/lambda/ruvic-*:*"
    }
  ]
}
    Nota lambda:ListFunctions no admite restricción por Resource (solo "*"), por eso list_functions siempre mostrará el nombre de todas las funciones de la cuenta, aunque solo pueda invocar las que coincidan con el prefijo.
  3. Crea el usuario IAM y adjunta la policy.

    En IAM → Users → Create user → marca "Provide user access to the AWS Management Console" en NO (es un usuario programático) → adjunta la policy del paso 2.

    [ Captura: creación de usuario IAM con la policy adjunta — reemplazar por assets/img/lambda-iam-user.png ]
  4. Genera las claves de acceso.

    En la página del usuario → pestaña "Security credentials" → "Create access key" → tipo "Application running outside AWS". Copia el Access Key ID y el Secret Access Key (este último solo se muestra una vez): los usarás en el formulario de Ruvic.

  5. Verifica el acceso desde la línea de comandos.

    Con el AWS CLI configurado con esas credenciales:

    aws lambda list-functions --region us-east-1

    Si responde con la lista de funciones (aunque esté vacía), el fabricante quedó listo. Anota estos valores para la siguiente sección: Access Key ID, Secret Access Key y región.

Permisos requeridos

Principio de mínimo privilegio: el usuario de Ruvic solo necesita estos permisos, limitados al prefijo de funciones dedicado. No otorgues lambda:*, lambda:CreateFunction, lambda:DeleteFunction ni lambda:UpdateFunctionCode.

Permiso Para qué sirve
lambda:ListFunctions Listar las funciones de la cuenta (lambda.list_functions)
lambda:InvokeFunction (por prefijo de función) Ejecutar una función con un payload (lambda.invoke)
logs:DescribeLogStreams, logs:GetLogEvents (por prefijo de log group) Consultar los logs recientes de una función (lambda.get_logs)

Configuración en Ruvic

Entra a Settings → Conectores, busca la tarjeta AWS Lambda y pulsa Configurar. Diligencia el formulario con los valores que obtuviste en la sección anterior:

Campo del formulario Valor
Access Key ID El Access Key ID del paso 4
Secret Access Key El Secret Access Key del paso 4. Se guarda cifrado como secreto: la interfaz no volverá a mostrarlo
Región de AWS La región donde están desplegadas las funciones (ej. us-east-1)
Timeout de conexión Opcional; 10 segundos por defecto

Guarda y pulsa Probar conexión — la plataforma verificará el acceso a Lambda en la región configurada.

[ Captura: formulario del conector AWS Lambda en Settings → Conectores — reemplazar por assets/img/lambda-form.png ]

Verificación

  1. Test de conexión exitoso.

    El botón Probar conexión debe responder: “Conexión exitosa a AWS Lambda en us-east-1”. La tarjeta del conector cambia a estado Configurado.

  2. Automatización mínima de prueba.

    Abre una conversación nueva con el agente y pídele: “Lista las funciones Lambda disponibles e invoca la función [nombre-con-prefijo-ruvic] con un payload vacío.” El agente debe listar las funciones e invocar la indicada, mostrando el resultado. Si lo hace, el conector quedó operativo de punta a punta.

Solución de problemas

Mensaje / síntoma Causa probable y solución
“Credenciales inválidas o sin permiso IAM suficiente” Access Key o Secret Key mal copiados, o la función invocada no coincide con el prefijo autorizado en la policy. Reintenta los pasos 2 y 4 de la sección 3.
“No se pudo conectar al servicio Lambda … (timeout)” La región configurada no coincide con la región real donde están las funciones. Verifica con aws lambda list-functions --region tu-region.
“La función no existe” Nombre de función mal escrito, o la función está en otra región. Usa lambda.list_functions primero para confirmar el nombre exacto.
El agente invoca la función pero “no hay logs” La función acaba de ejecutarse y CloudWatch aún no propagó los logs (puede tardar unos segundos), o falta el permiso logs:GetLogEvents sobre ese log group. Repite el paso 2 de la sección 3.
El conector aparece “Sin configurar” tras guardar Algún campo obligatorio quedó vacío. Ábrelo de nuevo y completa Access Key ID, Secret Access Key y región.

Preguntas frecuentes y notas de seguridad

¿El agente puede invocar cualquier función de mi cuenta?

Solo si tú lo permites en la policy IAM. Con el prefijo ruvic-* del ejemplo, el agente solo puede ejecutar (invocar) las funciones con ese prefijo, aunque list_functions siempre muestre el nombre de todas (esa acción no admite restricción por Resource).

¿Dónde queda guardado el Secret Access Key?

Como secreto en el almacén de credenciales de la plataforma, asociado a tu usuario. La interfaz nunca vuelve a mostrarlo; solo indica “definida”. Para cambiarlo, escribe uno nuevo en el formulario; para conservarlo al editar otros campos, deja el campo vacío.

Rotación de credenciales

Recomendado cada 90 días o según tu política: genera un nuevo Access Key en IAM → Security credentials, actualízalo en el formulario del conector, prueba la conexión, y luego desactiva/elimina la clave anterior desde la consola de AWS.

¿Qué hago si las credenciales se comprometen?

  1. Desactiva o elimina el Access Key de inmediato en IAM → Security credentials.
  2. Revisa la actividad reciente en AWS CloudTrail para ese usuario (invocaciones de funciones que no reconozcas).
  3. Genera un Access Key nuevo y actualízalo en el formulario del conector.

¿Puedo saber el resultado de una invocación asíncrona?

AWS no expone una API para consultar el resultado de una invocación Lambda por request id. Usa lambda.get_logs para revisar los logs recientes de la función después de una invocación en modo "Event", o diseña tu función para escribir el resultado en un destino consultable (una base de datos, una cola, etc.).

Buenas prácticas Usa siempre un usuario IAM dedicado con permiso de invocación limitado a un prefijo de funciones; nunca uses las credenciales root de la cuenta de AWS; revisa function_error en cada respuesta antes de asumir que la invocación fue exitosa; y evita compartir el Secret Access Key por canales no seguros.
